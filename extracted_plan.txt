This document provides the complete, authoritative implementation plan for evaluating and proving MedStreamMem (Option B: Domain-Weighted Fusion) within the KGARevion framework. The plan focuses on mathematically and empirically quantifying memory savings (Before vs. After values), tracking full precision and recall metrics, and evaluating accuracy gains across local Ollama models.

3. Detailed Before vs. After Memory Comparison Model
BEFORE Optimization (Unbounded Growth / Standard LRU / LFU):• Unbounded Baseline: Memory buffer grows linearly O(N) with query volume. For N = 1,000 queries, Memory Before Value ≈ 850 MB.• Standard LRU/LFU Flaw: Standard LRU evicts purely on recency (Δt), causing recent low-authority queries (τ = 0.50) to evict authoritative clinical guidelines (τ = 0.95). Standard LFU ignores recency decay.
AFTER Optimization (MedStreamMem: Domain-Weighted Fusion):• Hard Bounded Capacity O(K): Memory capacity is strictly capped at K items (e.g., K = 50). Memory Optimized Value ≈ 42.5 MB (95.0% RAM reduction).• Formula: Priority Score = (phi_hits * tau_trust) / (delta_t + 1.0). Protects high-authority clinical guidelines (tau = 0.95) and popular answers while maintaining constant RAM usage.

4. Phased Code Implementation Roadmap
• Phase 1: Memory Baseline Comparison Framework (src/memory.py)  Implement 4 comparative memory classes: UnboundedMemory (tracks Memory Before Value), LRUMemory, LFUMemory, and MedStreamMem (tracks Memory Optimized Value).
• Phase 2: LLM Accuracy & Precision Optimization  Benchmark local models: llama3.2:3b, llama3:latest (8B), and deepseek-r1:14b. Implement Chain-of-Thought (CoT) prompting in action/answer.py and metric functions in src/utils.py.
• Phase 3: Automated Experimentation & Metric Suite (scratch/benchmark_suite.py)  Build automated benchmark suite to evaluate all 4 memory baselines and 3 models, computing all 11 metrics and exporting CSV/JSON reports to results/paper_experiments/.
• Phase 4: React UI Visualizer (ui/react_dashboard.html)  Update React UI to display live Memory Before Value vs. Memory Optimized Value cards, Memory Reduction %, Precision/Accuracy stats, and eviction heatmaps.
5. Verification & Testing Plan
1. Automated Unit Test: Run scratch/test_memory_comparison.py to verify Memory Before vs. Memory Optimized values and high-trust retention under noise.
2. Multi-Model Test: Run test samples with llama3:latest and deepseek-r1:14b to verify precision and accuracy gains.
3. Full Benchmark Suite Run: Run scratch/benchmark_suite.py to export the complete report with Memory Before vs Optimized values to comparison_results.csv.
